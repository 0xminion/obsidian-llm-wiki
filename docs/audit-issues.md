## Remaining risks / unclaimed outcomes

- **Scale:** changed builds remain O(corpus); current query loading, whole-file state, flat directories, archives, and desktop indexing need separate work. See [proposed scaling architecture](scaling.md).
- **Semantic truth:** placeholder checks, exact quote matches, identity fingerprints, and type validation are deterministic guards, not an entailment checker. No fixed content count substitutes for source faithfulness.
- **Cross-store crashes:** SQLite, caches, manifests, Markdown, and external calls have separate commit boundaries. Checkpoints/retries are recovery aids, not a whole-vault transaction or exactly-once guarantee.
- **Source completeness and access:** site changes, unavailable transcripts, partial public abstracts, DNS/redirect races, parser/decompression behavior, and optional remote services remain separate risks. Do not infer universal extraction safety from one successful public URL/PDF.
- **Human ownership:** renderer protection can intentionally leave stale notes. `fix --apply` is a separate maintenance path; preview it and use `reviewed: true` where appropriate. Full-vault snapshots remain necessary.
- **Language/presentation:** active normalization preserves source-language titles/prose and only normalizes safe paths/references. Retained English-first utilities are legacy-only; language detection, explicit translation quality, and human equivalence decisions remain unverified semantic judgments.
- **Identity trade-offs:** conservative definition mismatches can split paraphrases; source-owned title reuse can preserve an ID through a meaningful definition change. Explicit canonical IDs can be selected incorrectly by a model. These decisions need review, not similarity-only auto-merge.
- **Testing boundary:** final suite/lint/optional integration receipts, installed-dependency checks, benchmark outputs, native platform runs, and live-model quality evaluation must be reported separately. No conclusion here should be read as “all checks passed.”
